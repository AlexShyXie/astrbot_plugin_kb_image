# astrbot_plugin_kb_image · 知识库图片发送
[![Version](https://img.shields.io/badge/version-v1.0.3-blue)]()
[![AstrBot](https://img.shields.io/badge/AstrBot-插件-green)]()
一个面向 **RAG 知识库场景** 的 AstrBot LLM 工具插件：当知识库检索文本中出现图片引用时，把对应的本地/远程图片**整组**发送给用户。
专治 RAG 的经典痛点——**同一病例的多张分图（a/b/c 多期相、跨页续图）被 chunk 切散后，AI 手里只有一个零散引用，发不出完整图组**。本插件在启动时解析全部 md 的排版结构，建立"图 → 所属图组"的映射，任何一张图的引用都能自动还原为它所在的完整 figure 块。

## ✨ 核心特性
| 特性               | 说明                                                         |
| ------------------ | ------------------------------------------------------------ |
| 🔗 整组补齐         | 传入任意一张图的引用，自动补齐同组的其余分图（同一病例的 CT/MRI a,b,c…） |
| 📖 题注回传         | 发送成功后把对应题注回传给 LLM（如"图7-2-13 肝海绵状血管瘤"），解说直接对题 |
| 🧵 "（续）"体例支持 | 肿瘤图谱类书籍"疑难病例（续）"的跨页 A~K 连排图可正确合并为一组 |
| 🛡️ 引用容错         | 兼容文件名 / `./images/xxx.jpg` 相对路径 / 绝对路径 / `file://` / http(s) URL 五种形态 |
| 📦 零 token 索引    | 全部结构分析在启动时完成，运行期不消耗任何模型 token         |
| ⚙️ 可控发送         | 单次发送上限、超限提示、失败引用明确回告防编造               |
## 🏗️ 工作原理
### 启动时的三层索引
```
① 图片索引   扫描 kb_root 下所有图片 → 文件名 -> 绝对路径
② md 结构索引 解析 md_root 下全部 md，按医学书排版规律切分"figure 图块"
③ 组/题注索引 反向映射：每张图 -> 所属图组全体成员 + 该块第一条题注
```
md 分块采用三条硬边界规则（可按书籍实际体例调整正则）：
- 行首出现编号图注（`图7-2-13 …`）→ 当前图组收尾
- 行首出现章节标记（`#`、`【】`、`**加粗**`）→ 边界
- 图片之间夹带超过阈值的长正文 → 边界；纯空白 / 短子标注（`a.` `b.`）/ 同行多图 → 归入同组
- 含"（续）"字样的题注不断组，直到安全阀张数兜底
### 运行时的请求流程
```
LLM 传来引用串 → 拆分/去重 → 逐一解析定位
    ├─ 命中本地图 ─→ 查组索引补齐兄弟图 ─┐
    └─ URL           原样保留            ├─ 合并去重 → 截断至上限 → 一条消息批量发送
                                          ↓
                              回传结果 + 图注给 LLM 继续解说
```
## 📥 安装
1. 将本文件夹放入 AstrBot 的 `data/plugins/` 目录（或通过插件市场安装后覆盖）
2. 重启 AstrBot，观察日志出现三行索引完成信息：
```
[kb_image] 图片索引完成，共 N 张
[kb_image] md索引完成: X 个文件, Y 个图号
[kb_image] 组索引完成: Z 张图可自动补齐
```
## 📁 数据目录要求
### 图片目录（必填）
所有图片文件的根目录，默认为：
```
data/plugin_data/astrbot_plugin_kb_image/images/
```
- 文件名需与 md 中引用的一致（epub 导出的内容哈希名天然全局唯一）
- 支持子文件夹随意嵌套，插件按文件名递归建索引
### md 目录（可选但强烈建议）
md 文档根目录，**按书籍分子文件夹存放**：
```
data/plugin_data/astrbot_plugin_kb_image/md/
├── 医学影像诊断学/
│   ├── 第一篇_第一章_第一节.md
│   └── ...
├── 肿瘤影像诊断图谱（第2版）/
│   ├── 01_第一篇 头颈部肿瘤__05_疑难病例分析.md
│   └── ...
└── ...
```
> 书籍文件夹命名无需与文中引用严格一致：插件做包含式匹配时会剥掉 `·` `-` `（）` 等符号再比对，`中华影像医学·肝胆胰脾卷` 与 `中华影像医学-肝胆胰脾卷` 视为同一本书。
>
> 未配置 md 目录时插件仍可用，但没有整组补齐和题注能力（只发单张）。
## ⚙️ 配置项
| 配置项             | 类型   | 默认值   | 说明                                                         |
| ------------------ | ------ | -------- | ------------------------------------------------------------ |
| `kb_root`          | string | 空       | 知识库图片根目录。留空用上述默认路径                         |
| `md_root`          | string | 空       | md 文档根目录。留空用默认路径                                |
| `post_send_prompt` | text   | 内置文案 | 图片发送成功后回传给 LLM 的提示语，支持 `{count}` 占位符替换为实际发送张数 |
## 🤖 LLM 工具说明
注册了一个工具供模型调用：
### `send_kb_image(image_refs)`
- **触发时机**：用户想看案例图/影像图/示意图，且知识库检索片段中出现了 `![](./images/xxx.jpg)` 或图片 URL 形式的引用
- **参数**：多个引用以逗号/分号/换行分隔，可混合文件名、相对路径和 URL
- **防错设计**：
  - docstring 明确告知模型"有多少传多少，禁止为凑齐多次调用"
  - 失败引用会逐个回告："以下引用未找到，不要凭空编造"，引导模型自纠
  - 发送数受 `MAX_SEND_IMAGES` 上限保护（默认 24）
## 💡 使用示例
**场景一：chunk 把同一图的三张分图切开**
> 用户：肝海绵状血管瘤 MRI 上有什么特征？
> （检索只召回了含第二张分图的 chunk）
> AI 调用 `send_kb_image("./images/c91aa...jpg")`
> 插件查组索引 → 自动补齐平扫/增强/MRI 共 4 张一次发出
> 回传给 AI：「已成功发送 4 张图片给用户，对应知识库图注：图7-2-13 肝海绵状血管瘤。请结合图片解答…」
> **场景二：肿瘤图谱的疑难病例（续）**
> 一个病例 A~K 共 11 张分图分布在"疑难病例""疑难病例（续）"两个段落，
> 无论检索命中哪一段的哪张图，都会补出全病例图组（受 16 张安全阀保护）。
## 📊 健康度自检（日志判读）
启动日志三行的比例关系可以快速判断数据是否对齐：
```
15669 张磁盘图片  ≥  组索引中的成员数（多图块）+ 其余单图块
3917 个图号 ÷ 多图块图片数 ≈ 每个编号图的平均分图数（2~4 为正常）
"未找到图片"警告持续为 0      ← md 引用与磁盘图片完全对齐
"磁盘缺失"/构建失败偶发       ← 抽查对应文件名是否 OCR 断名
```
## ❓ FAQ
**Q：为什么"可自动补齐"的张数比图片总数少？**
正常现象。单图块（一个 figure 只有一张图，如解剖示意图、正常影像表现）没有可补齐的兄弟图，不进入组索引，但仍能被 `send_kb_image` 正常单独发送并附带题注。
**Q：发送图片多了会被刷屏吗？**
受 `MAX_SEND_IMAGES`（24）与 `MAX_GROUP_SIZE`（16）双重限制；超过部分不会发送，且回传文本会告知模型"另有 N 张超出单次上限"，由模型决定是否提示用户。
**Q：没有检索到任何带引用的内容怎么办？**
当前版本依赖检索提供引用。如有"用户点名要看某书某图但完全没命中"的高频需求，可启用预留的书名/图号/关键词检索方案（代码中已含 `fig_index`、`md_meta` 等基础设施）。
**Q：我的书不是"图在前题注在后"的排版？**
修改 `main.py` 顶部的四个结构正则（`CAPTION_NUM_RE` 等）即可适配其他体例；分块逻辑集中在 `_parse_blocks`，改动面很小。

## 手动存照片说明

### MD 标准格式模板

```markdown
# 第7章 某某疾病
这里是正文段落，写你整理的要点。
正文结束后的下一组图开始：
![分图a](img_a1b2c3d4e5f6.jpg)
（a）左心室长轴切面
![分图b](img_9876fedcba.jpg)
（b）彩色多普勒血流图
图7-2-13 二尖瓣狭窄的超声表现
---
（下一组图，单图的写法）
![示意图](img_1122334455.jpg)
图7-3-01 主动脉夹层分型示意图
```

### 推荐排版顺序

```
图片引用（连续罗列，不夹其他内容）
  ↓ 每张图下一行短标注（可选，如"（a）xxx"）
  ↓ 最后一条总图注（必须有，含图号）
  ↓ 正文段落
```

---

### 四、格式规则详解
#### 1. 图片引用
必须用标准 Markdown 语法：
```markdown
![描述文字](文件名.jpg)
```
- **只写文件名即可**，不必写路径，插件按文件名全局索引查找。
- 括号内**不能有空格和括号**，否则无法识别。
- 支持完整的本地路径、`file://` 协议、`http(s)://` URL（URL 图片原样发送，不参与组补齐）。
- 引用与实际文件名不一致时会做模糊匹配兜底（子串匹配 / 编辑距离匹配），但**请尽量使用完全一致的文件名**。
> **给公众号图片重命名的建议**：用 md5 或 `章节号-图号-序号.jpg` 等唯一命名，避免 `image001.png` 这类重名文件互相覆盖。
#### 2. 图注（最关键！决定能否按图号检索）
图注放在**图片引用后面紧接着的几行内**，支持两种写法：
**写法一：标准图号式（推荐）**

```markdown
图7-2-13 二尖瓣狭窄的超声表现
```
- 图号支持多种分隔符写法，都会被归一化到同一索引：
  - `7-2-13`、`7．2．13`、`7—2-13`、`7、2、13` 等写法均等价
  - 最多 3 段数字，尾部的分图字母会自动剥掉（`图7-2-13b` → `7-2-13`）
- 行首可以带 0~4 个 `#`，如 `## 图7-2-13 xxx` 也合法。
**写法二：宽松式（无编号时使用）**
```markdown
图：二尖瓣狭窄的超声表现
【图：主动脉夹层】
```
前可带 `#`、`【`、空格。
- 没有官方编号时可**自编图号**，如 `图公众号-001`，只要符合 `图x-x` 数字模式即可被索引。
#### 3. 多分图（同一案例的多张图）
同一案例的多张图**连续罗列**，每张图下允许一行**短子图标注**：
```markdown
![分图a](img_aaa.jpg)
（a）左心室长轴切面
![分图b](img_bbb.jpg)
（b）彩色多普勒血流图
图7-2-13 二尖瓣狭窄的超声表现
```
支持的子图标注格式：
- `（a）xxx`、`(b) xxx` —— 字母 a~k
- `① ② ③` —— 序号 ①~⑩
限制：
- 每行标注 ≤ 30 字符，整个图组内非标注文字累计 ≤ 60 字符
- **一个图组只写一条总图注**（放最后），组内所有分图都会映射到这条图注
- 单个图组最多 16 张图，超出会被强制断组
#### 4. "（续）"写法（同一图组被长文字隔开时）
```markdown
图7-2-13 二尖瓣狭窄的超声表现（续）
```
- 支持 `（续）`、`(续)`、`continued`
- 续段内的任意文字（包括 `**说明**`）都不会断组，会并入当前图组
- 适用于公众号原文被切分成多段的情况
#### 5. 什么会"截断"一个图组（注意避坑）
以下情况会结束当前图组，**不要把它们插在同一组图的中间**：
- 行首是 `#`、`**`、`【` 开头的章节/标题行（续段模式除外）
- 累计正文超过 60 字符（且不是合法子图标注）
- 空行 + 长正文段落

#### 常见坑提醒 ⚠️

| 坑                       | 说明                                                         |
| ------------------------ | ------------------------------------------------------------ |
| 单次最多发 24 张         | 超出会自动截断，并在结果中提示                               |
| 图片引用括号内不要有空格 | `![] (a b.jpg)` 无法识别                                     |
| 图注别写太长             | 图注属于"短文字"额度（图组内累计 ≤60 字符），长描述请放到图组之后的正文段落 |
